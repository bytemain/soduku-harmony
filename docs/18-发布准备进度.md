### 工程与 CI 改动

- `hvigorfile.ts` 仅保留签名 override，去掉强行写入版本 `1 / 100000` 的函数，使版本由 `AppScope/app.json5` 统一提供。保留 `data.json` 与签名环境变量机制，后续支持外部配置和 alias，修正为官方 `keyPassword`。本机 Hvigor 要求 DevEco 密文，正式签名改用官方 SDK；密码由脚本从仓库外受限文件读取并脱敏，不写源码或进程命令行。
- `entry/hvigorfile.ts` 不再因为 `CI` 环境变量存在就跳过原生执行。只有显式 `HYPIUM_COMPILE_ONLY=1` 才禁用 `GenerateUnitTestResult`，并输出“未执行测试”的提示。
- 新增 `scripts/run-hypium-tests.mjs`：删除已知旧结果文件，强制取消 compile-only，实际调用 Hvigor，检查退出码、检查新报告并逐项核对结果；保留新报告到 `test-results/native-unit-test-result.txt`。没有新报告、空/截断报告、零用例、结果/汇总数量不符、未知状态、Failure/Error/Ignore 都会失败。
- 新增 `scripts/verify-hypium-results.mjs`，供结果复核使用。不能只看 `BUILD SUCCESSFUL` 或 shell 返回码；原始 342 例报告的 1 例失败已被此检查器正确拒绝。
- Linux CI 的 `test` job 明确命名为 **Compile native tests (NOT executed)**，只验证编译，不伪装成执行通过。另有可手动触发的 `Native unit tests` 工作流，要求安装 DevEco 的可信 macOS self-hosted runner，标签 `self-hosted, macOS, harmonyos`。该 runner 尚未在 GitHub 配置或运行。
- CI 依次保存 debug HAP 和 release APP 为 review artifacts，缺少产物时失败。移除了原先仅凭编译通过、标签触发的自动公开 GitHub Release；当前不会自动上传华为市场或公开发布制品。未配置正式签名时产物仍是未签名包。
- 使用新的显式 job 名称后，如仓库规则将旧 check 名作为必需项，维护者需要对应调整所要求的 check 名。没有在本次修改任何远程分支保护配置。Linux 编译检查不能替代发布前原生测试、真机和签名核验。

原生测试运行方式（在英文路径工程内、DevEco Node/Java/ohpm/SDK 环境已配置时）：

```sh
node scripts/run-hypium-tests.mjs
```
