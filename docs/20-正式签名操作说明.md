## 推荐入口：对现成 Release APP 使用官方 SDK 签名

脚本：`scripts/sign-release-app.py`。默认输入 `release-artifacts/good-sudoku-1.0.0-unsigned.app`，默认输出 `release-artifacts/good-sudoku-1.0.0-signed.app`。它不创建密钥、不发证、不修改后台、不上传应用，也不重复构建或运行整套游戏测试。

材料默认放在仓库外的目录 `~/.ohos/release/io.oranix.soduku.mini/`，目录权限 700：

| 文件 | 含义 |
| --- | --- |
| `sudoku-release.p12` | 已创建的独立发布密钥库；权限 600 |
| `sudoku-release.csr` | 对应 CSR；已创建 |
| `sudoku-release.cer` | 已签发并下载的正式发布证书链；实际到期时间 2029-11-02 07:09:41 UTC |
| `sudoku-release.p7b` | 已生成并下载的本应用 release Profile；后台有效期展示至 2029-11-02 |
| `keystore-password.txt` | 已创建的受限单行密码文件；权限 600，勿复制到源码或聊天 |

本应用默认 alias 为 `sudoku_release`，可通过 `--key-alias` 或 `SIGNING_KEY_ALIAS` 改写。默认 store/key 密码共用同一受限文件；需要分开时使用 `--key-password-file`。也可由安全的外部进程提供 `RELEASE_KEYSTORE_PASSWORD` / `RELEASE_KEY_PASSWORD`，不要把密码字面量写进 shell 命令、历史或日志。

材料全部就绪后，先做只读公开材料核验：

```sh
python3 scripts/sign-release-app.py --check
```

`--check` 检查私密文件是否存在及权限，但**不读取密码内容、不签名**。它核对现成 APP 为本包名的非 debug release，CSR 自签名有效；从证书链按 CSR 公钥选择唯一 leaf，不假设 AGC 链首张就是 leaf；检查 leaf 有效期；调用官方 `verify-profile`，核对 Profile 为 release、包名完全一致、分发证书公钥及完整 leaf 指纹一致。Profile 证书接受 PEM 或 base64 DER。

核验通过且签名材料获得授权使用后，执行：

```sh
python3 scripts/sign-release-app.py
```

如需明确指定目录或输入：

```sh
python3 scripts/sign-release-app.py \
  --materials-dir "$HOME/.ohos/release/io.oranix.soduku.mini" \
  --key-alias sudoku_release \
  --input release-artifacts/good-sudoku-1.0.0-unsigned.app
```

脚本用本机 DevEco 自带的 Java 与 `hap-sign-tool.jar sign-app`。密码写入材料目录中临时子目录下的 600 权限 Java `@argfile`，不放入操作系统进程参数；签名调用结束后在 `finally` 中删除该文件。官方工具输出先在内存中脱敏，日志写到材料目录的 `signing-last-run.log`（600），不保存未处理的 stdout/stderr。

签后调用官方 `verify-app`，核对提取的 leaf 公钥/指纹、提取的 Profile 与签前已核验文件一致，并验证 APP ZIP 完整性和嵌入 HAP 内容未变。通过后才复制到最终输出路径，同时写同名 `.verification.json`，记录 SHA-256、版本、证书指纹及验签范围。失败时不复制本轮签名产物；如输出路径原本已有文件，不能把旧文件误认成本轮通过，应以本轮退出码和对应验证记录为准。

**签名范围是标准 APP 外层签名。** 本机官方 Hvigor 的 `PackageApp` 默认取未签模块产物；`appWithSignedPkg=true` 才另做含已签内部包的 `all.app`。本脚本复现默认 `SignApp`，不宣称内嵌 HAP 已签或已递归验签。它不能替代实际设备试玩、正式截图、资质材料或商店审核。

## Hvigor 环境签名的兼容修复

`hvigorfile.ts` 已将原先误用的 `keyPwd` 改为官方 schema 的 **`keyPassword`**。`keyPwd` 只属于 SDK CLI 参数；旧 `data.json` 字段被兼容归一化。支持 `SIGNING_KEY_ALIAS`，缺省仍为 `ide_demo_app`，并在部分签名材料缺失时失败，不静默产出未签名包。

本机 DevEco 26 的 Hvigor 对 `keyPassword` / `storePassword` 无条件调用 `DecipherUtil.decryptPwd`，需要 **DevEco 密文以及密钥库同目录的 `material/{fd,ac,ce}`**。因此不能把 `keystore-password.txt` 中的原始随机密码直接填到 Hvigor `KEY_PASSWORD` / `KEYSTORE_PASSWORD`；长十六进制明文也不是 DevEco 密文。脚本推荐路径避免依赖 IDE 内部加密 API。

已有官方 DevEco 加密配置时，可用外部 `SIGNING_CONFIG_FILE`，内容保持 `{"signingConfig": {...官方 material 字段...}}`；或继续使用原有忽略文件 `data.json`。没有文件配置时，环境变量 `SIGNING_CERT`、`SIGNING_PROFILE`、`SIGNING_KEY`、`SIGNING_KEY_ALIAS`、`KEY_PASSWORD`、`KEYSTORE_PASSWORD` 提供完整配置。密码字段在此处必须为对应的 DevEco 密文。不要把签名文件或密码写进受版本控制的 `build-profile.json5`。

`SIGNING_DISABLED=1` 明确跳过全部签名配置，用于继续构建未签名包；`SIGNING_REQUIRED=1` 可要求缺材料时失败。只有构建需要英文路径时继续使用既有 ASCII staging，本脚本本身针对现成 APP，不需要创建新的 staging。
